# Contributing

[Home](README.md)

Contributions welcome from NTL associates and independent learners.

- Keep the format: **topic → resource → small project**.
- Prefer official docs and the creator's original video or website.
- Open links before submitting; check the destination and relevant version.
- Label paid resources and older tutorials.
- Keep new topics optional unless they are needed for the next step.
- Submit a focused pull request with the reason and verification date.

Avoid theory sections, unsupported industry claims, and duplicate resource lists.

## Workflow and review

- For non-trivial changes, open an issue with the affected track, reason, proposed resources, and target versions. Get maintainer agreement before adding a track or changing milestones. Small fixes can go straight to a PR.
- Fork the repository and use a focused branch such as `docs/unity-input`. Keep each PR to one topic and use a clear commit message.
- Target `main`. Include a summary, reason, verification method and date, and the engine, SDK, or OS versions checked (or mark versions as not applicable).
- Verify links and documentation; run changed samples or builds where relevant. State what you tested and any checks you could not perform.
- Keep generated files, build outputs, caches, and local editor settings out of Git. Use Git LFS for necessary large binary assets; do not commit them directly.
- Maintainers review accuracy, learning value, and repository fit before merging. Address feedback and allow at least 48 hours before requesting an update.
